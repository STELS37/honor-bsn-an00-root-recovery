# HONOR BSN-AN00 — временный root без разблокировки загрузчика

> Практический кейс: HONOR BSN-AN00, Android 16, ядро `6.12.58-android16-6-g3a7ac1674240-abogki541502914-4k`. Исследование и повторное восстановление root, а не прошивка телефона.

## Проверенный результат (6 ноября 2026)

На указанном устройстве через [CVE-2026-98260](https://github.com/woshigenm/CVE-2026-98260) удалось получить `uid=0` и загрузить `kernelsu.ko` без OEM unlock и без изменения boot/vendor/system-разделов. В зафиксированной последовательности присутствовали `KSU_CHAIN_HELD`, `KSU_CHAIN_OK`, `GRANT_ROOT rc=0 uid=0`, `ROOT_STAGE_OK`, `DONE`. `PARKED=1` означает, что отдельные процессы остаются удерживаться после эксплуатации. После перезагрузки временный root исчезает.

**Важно различать:** полученный UID 0, загруженный LKM, выдачу прав приложениям через KernelSU и сохранение этих прав при перезагрузке. Они проверяются отдельно. На locked bootloader загрузка LKM в оперативную память не делает его постоянным.

## После перезагрузки: проверенный ручной путь

1. Запустить **Shizuku** в режиме Wireless Debugging/ADB (сопряжение с устройством обычно сохраняется; сама служба после перезагрузки запускается снова).
2. Открыть **CVE-2026-98260 Root**.
3. `1. 授权 Shizuku` — проверить разрешение (повторно выдавать не требуется, если оно осталось).
4. `2. 部署资产` — восстановить актуальные файлы в `/data/local/tmp/cveapp`.
5. `3. 开始提权` — запустить штатную проверенную цепочку.
6. Проверить `su -c id` и состояние `kernelsu` в `/proc/modules`, затем разрешить root нужным приложениям в менеджере KernelSU.

Исходная Root App сама проверяет выбранный профиль ядра и наличие уже загруженного KernelSU. В нормальном сценарии повторное нажатие после успешной загрузки модуля должно перейти к проверке, а не устанавливать второй модуль.

## Быстрое и автоматическое восстановление

Технические варианты и фактическое состояние на BSN-AN00 описаны в [docs/BOOT-RECOVERY.md](docs/BOOT-RECOVERY.md).

- **Рабочий сегодня:** повторный запуск Shizuku и трёхступенчатый процесс через штатную Root App. Без компьютера при настроенном Wireless Debugging.
- **Ускорение:** автоматический запуск Shizuku после загрузки через открытые форки Shizuku; работоспособность конкретно на BSN-AN00 ещё нужно подтвердить.
- **Полный автозапуск root:** отдельная задача интеграции и проверки — нельзя считать реализованной лишь потому, что получен временный UID 0. Обязателен контроль состояний и исключение параллельных запусков.

### Быстрое восстановление после перезагрузки

Для запуска без компьютера проект использует **Shizuku+ Drop-In (автозапуск через Wireless Debugging)** и **aShell You (плитка Quick Settings, выполняющая локальную shell-команду)**. Проверяющая оболочка `scripts/restore-root.sh` добавляет проверку точной модели и версии ядра, обнаружение `PARKED`, защиту от одновременного запуска и делегирует уже работающему upstream `run.sh`. Инструменты не изменяют boot-раздел и не заявляют постоянный root.

Порядок без компьютера: включить Shizuku через Wireless Debugging, выполнить первичное развёртывание ресурсов в официальной Root App, затем запускать её штатную цепочку из aShell You. Для автоматического восстановления **самой Shizuku** смотрите [документацию Shizuku+](https://github.com/thejaustin/ShizukuPlus/wiki/Service-Connection). На HONOR BSN-AN00 запуск Shizuku+ при каждой перезагрузке и восстановление KernelSU одной плиткой **ещё требуют проверки**.

Получить закреплённые официальные APK одним скриптом: `python3 scripts/fetch-apps.py --profile manual` или `--profile auto-shizuku`. Все версии и контрольные суммы находятся в [apps/manifest.json](apps/manifest.json). Публичная GitHub Actions сборка также собирает архив приложений для загрузки.
